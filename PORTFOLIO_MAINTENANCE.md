## 🔁 1. Three-Beat Case Study Addition Blueprint

When adding future builds to the portfolio site, every new project follows this exact three-beat shape:

```text
┌─────────────────────────┐     ┌──────────────────────────┐     ┌─────────────────────────┐
│     BEAT 1: PROBLEM     │ ──> │   BEAT 2: WHAT I DID     │ ──> │  BEAT 3: WHAT CAME OF IT │
│ The operational gap or  │     │ System architecture, ML  │     │ Ground-truth metrics,   │
│ real-world bottleneck   │     │ models & AI tools used   │     │ operational outcome     │
└─────────────────────────┘     └──────────────────────────┘     └─────────────────────────┘
Beat 1: The Problem (Context & Friction)

Prompt to answer: What operational bottleneck, manual waste, or business gap required solving?

Style constraint: Frame using public-safe, decision-support terminology without hype or unverifiable claims.

Beat 2: What I Did (Technical Execution & Architecture)

Prompt to answer: What backend stack, ML model, data engineering pipeline, or prompt architecture was deployed?

Style constraint: Explicitly document leakage-prevention strategies, AI pairing tools used (e.g., Claude 3.5 Sonnet / FastAPI), and key design choices.

Beat 3: What Came of It (Empirical Outcome & Deliverable)

Prompt to answer: What were the validated evaluation metrics (F1, ROC-AUC) or production operational outputs?

Style constraint: Provide live links to deployed HTML/web interfaces, repository notebooks, and actionable decision playbooks.
